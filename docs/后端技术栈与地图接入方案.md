```text

```

登录：`POST /api/auth/login`  
当前用户：`GET /api/auth/me`  
退出：`POST /api/auth/logout`

默认 Token：HS256，86400 秒有效。实现位置：[`backend-python/app/core/security.py`](../../project/backend-python/app/core/security.py)。

当前是演示级鉴权：密码为明文比对，`.env` 里有默认 SECRET_KEY。正式实现时必须改为密码哈希、随机密钥和更合理的 Token 生命周期。

## 四、当前数据层的真实状态

### 4.1 API 主要使用进程内 `mock_data`

以下路由直接读取或修改 `app/data/mock_data.py`：

- `/api/auth/*`
- `/api/dashboard/*`
- `/api/meta/*`
- `/api/records/*`
- `/api/violation/*`

因此当前行为是：

- 启动时生成约 30–60 条演示记录。
- 看板统计从内存记录派生。
- 审核、删除、批量删除、类别启停和识别项阈值修改的是内存对象。
- 服务重启后，这些运行时修改会丢失。

### 4.2 SQLAlchemy/SQLite 已有但尚未接管运行时

项目已有 `app.db`、`app/db/database.py`、`app/db/models.py`、`app/db/seed.py` 和 `init_db.py`。

已定义的 ORM 实体：

```text
Category, Scene, Team, Unit, Version, ProcessStatus,
User, ViolationRecord, Detection, ReviewHistory,
CategoryAdmin, ReviewLog, FenceConfig, RecognitionItem
```

但 API 路由没有普遍使用 `Depends(get_db)`、SQLAlchemy 查询和事务提交，仍然以 `mock_data` 为主。

### 4.3 推荐迁移顺序

1. 保留现有 API 契约和 `{code,message,data}` 结构。
2. 增加 `get_db()` 依赖。
3. 先迁移用户、违章记录、Detection、ReviewHistory。
4. 再迁移类别、识别项、电子围栏和审核日志。
5. 最后将 Dashboard 统计改成数据库聚合查询。
6. 迁移期间不要让同一个接口一部分读 SQLite、一部分写 `mock_data`。

## 七、地图功能现状

当前项目还没有真正的 GIS 地图 SDK，现有代码只有：

- 电子围栏页面的 SVG 预览。
- 详情页视频帧上的 SVG 围栏叠加。
- `FenceConfig.points`。
- 识别框和围栏的图片像素坐标缩放。

当前缺少：

- 地图 SDK。
- 站点中心点和地图缩放级别。
- 吊车、摄像头、雷达、音柱、录像机、边缘盒经纬度。
- GIS 电子围栏 GeoJSON。
- 地图告警点和轨迹接口。

### 关键区别：像素坐标不是 GIS 坐标

现有契约里的围栏：

```json
{
  "points": [[200, 175], [1080, 175]],
  "color": "#ff00ff"
}
```

这是基于 `1280 × 720` 视频帧的像素坐标，只适合绘制视频画面内的警戒线，不能直接交给地图 SDK。

实现地图时必须分开：

```text
视频帧坐标：像素 x/y，给 AI bbox 和画面围栏使用
GIS 坐标：经度/纬度，给地图点位、真实围栏和轨迹使用
```

## 八、公共地图 API 方案

### 方案 A：高德地图 JS API（推荐）

适合中国大陆吊装场站，理由是中文底图、道路、POI、地理编码和覆盖物能力较完整，适合展示吊车、摄像头、雷达、音柱、围栏和告警。

注意事项：

- 需要申请 Web Key。
- 需要配置安全密钥、域名白名单和配额。
- 默认使用 GCJ-02 坐标。
- Key 使用 `VITE_*` 环境变量，不提交到 Git。

### 方案 B：腾讯位置服务 JS API

可以作为高德的国内备选，适合中文地图、位置搜索、地理编码和地图覆盖物。需要独立申请 Key，并单独确认坐标体系与配额，不要与高德坐标直接混用。

### 方案 C：天地图

适合政企、能源、测绘等对国产底图或合规性更敏感的场景。需要 Token，图层组合和接入流程通常比 Leaflet 复杂。

### 方案 D：Leaflet + OpenStreetMap

适合没有地图 Key 的本地原型。Leaflet 轻量、易与 Vue 集成，但公共 OSM 瓦片不等于无限免费生产服务，必须遵守 Tile Usage Policy；高并发和商业化场景应使用自有或商业瓦片服务。

### 方案 E：MapLibre GL JS

适合后续需要矢量瓦片、3D 吊装场景、轨迹动画或自定义地图图层的阶段。当前第一版不建议直接采用，因为底图、瓦片和运维复杂度更高。

### 推荐决策

```text
中国大陆正式场景：高德地图 JS API
本地无 Key 原型：Leaflet + OSM
政企/国产底图要求：天地图
后续 3D/矢量瓦片：MapLibre GL JS
```

## 十一、坐标系策略

| 坐标系 | 常见来源/用途 |
|---|---|
| WGS84 | GPS/北斗设备原始定位、国际标准 |
| GCJ-02 | 高德、腾讯等中国大陆互联网地图 |
| BD-09 | 百度地图 |
| 图片像素坐标 | 当前视频帧 bbox 和画面内围栏 |

推荐做法：

1. 后端保存设备原始 WGS84，并保留原始数据。
2. 对外给高德/腾讯时转换成 GCJ-02，或者在明确的地图适配层转换。
3. 对外给百度时再转换成 BD-09，不把 BD-09 覆盖回原始数据。
4. 数据显式携带 `coordinateSystem`，不要通过字段名猜坐标系。
5. 视频帧识别框永远保留像素坐标，不能和 GIS `geometry` 共用字段。

## 十四、建议实现顺序

### 阶段 1：静态地图联调

- 先用高德或 Leaflet 创建 `SiteMap.vue`。
- 使用前端静态 JSON 绘制场站、吊车、摄像头、雷达、音柱、围栏和告警点。
- 验证深色主题、图例、点位筛选、信息窗体和风险颜色。

### 阶段 2：后端地图概览接口

- 增加站点、设备点位、GIS 围栏和地图告警结构。
- 实现 `/api/sites/{siteId}/map-overview`。
- 在设备和告警中补充 `status`、`riskLevel`、`lastHeartbeat`、`position`。

### 阶段 3：接入实时状态

- 告警发生时显示地图风险点。
- 点击点位打开设备详情或事件证据抽屉。
- 将事件视频帧识别结果与地图设备/围栏关联。

### 阶段 4：数据库迁移

- 将站点、设备、围栏和事件迁移到 SQLAlchemy。
- 用 SQL 聚合替代 `mock_data` 的 Dashboard 统计。
- 增加唯一约束、索引、时间字段和软删除字段。

### 阶段 5：生产化

- 密码哈希、随机 SECRET_KEY、刷新 Token 或短期 Access Token。
- 日志、审计、限流和异常监控。
- 地图 Key 白名单和配额监控。
- 地理范围查询、分页和设备轨迹查询。

## 十五、当前阶段推荐决策

```text

后端：FastAPI + Pydantic + SQLAlchemy 2.0 + SQLite
认证：先保留 JWT 接口形态，随后补充密码哈希
```
